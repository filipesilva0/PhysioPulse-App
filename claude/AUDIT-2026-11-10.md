# Clínica — full app audit (10 Nov 2026)

**How this was done.** I read the project docs, the whole route table of the server, and the UI code for Login, App shell, Settings, Team, the schedule views and the main forms. I built the app (`tsc` clean, `build` and `build:preview` OK) and drove the browser preview with Playwright through every page, every Finance and Settings section, every patient tab, as owner, therapist and reception, in light and dark, at 1440, 1024 and 700 px.

**Not covered.** The real desktop app on Windows/Mac, the live server, the server e2e suites (not re-run) and the real AI model. Findings marked *(code)* come from reading code, the rest were reproduced in the preview.

---

## 1. Executive summary

**Grade: C+** — a B+ core wrapped in a D settings and account layer.

The clinical, schedule and money flows are real, careful and well tested. But a large part of Settings is a mock-up that looks live, several screens show hardcoded facts as if they were true (backup time, database encryption, the signed-in person), typed work is lost silently in four different ways, and there is no way to change or recover a password. None of that is acceptable once real patient data goes in.

**Top 3 strengths**

1. **Safety model is thought through.** Roles enforced on the server, append-only access log, signed notes locked by trigger, hold-to-delete, Undo on reversible actions, AI that proposes and never saves.
2. **Visual system is coherent.** Tokens, page colors, dark mode, 1024 px layout and the frosted frame all hold up; no overflow or clipped text at the minimum window size.
3. **Portuguese-clinic fit.** Prescriptions that count down, ERS complaint deadlines, VAT-exempt marking, reimbursement packs, accountant export. These are the hard, specific parts and they exist.

**Top 3 critical flaws**

1. **Settings is mostly a facade.** Clinic details, security, patient portal, payment methods, invoicing and "Server and backups" save nothing; the backup page shows a fake "last backup: today, 03:00" and a "Back Up Now" button that does nothing.
2. **Silent data loss.** A half-written progress note vanishes on a tab switch; unsaved anamnesis vanishes on navigation; Esc throws away a filled form; Ctrl+N replaces an open form.
3. **No account lifecycle.** No change password, no forgot password, no lost-phone recovery for two-step, no profile edit, and the server has no routes for any of them.

## 3. Detailed critique, by severity

### Critical

**C1. "Server and backups" shows invented facts.**
- **Location:** Settings › Servidor e cópias (`ServerSet` in `src/pages/Settings.tsx`).
- **Problem:** "zimaos.tail-clinica.ts.net", "PostgreSQL num volume encriptado", "Última cópia: hoje, 03:00" are literal strings. The disk is in fact not encrypted (your 7 Nov decision). "Fazer cópia agora" only shows "Cópia iniciada (exemplo)". If the nightly backup stopped a month ago this screen would still say today.
- **Fix:** Add `GET /system/status` (server version, real address, newest backup file name and time, off-site state) and `POST /system/backup`. Show a warning on Today when the newest backup is older than 36 hours. Until then, remove the page.

**C2. Typed clinical work is lost without warning.**
- **Location:** Patient file › Evolução and Anamnese; every sheet.
- **Problem (reproduced):** free-text in a new note is gone after clicking Testes and back; unsaved anamnesis is gone after clicking Hoje; Esc closes a filled New Patient sheet with no question; Ctrl+N replaces an open sheet; Ctrl+2 changes the page behind an open sheet.
- **Fix:** Keep the note draft in state above the tabs and autosave it as a server draft every few seconds (the draft route exists). Guard navigation when anamnesis is dirty. Make Esc ask "Discard changes?" when a sheet has edits. Ignore app shortcuts while a sheet or alert is open.

**C3. Signed notes record values nobody entered.**
- **Location:** Note builder (`Notes` in `src/pages/Patients.tsx`).
- **Problem:** Sliders start at Pain 5, Rotation 60°, Function 5 and are always saved. Type one sentence, sign, and the locked record says "Dor 5". It then feeds the history line, the AI rewrite and the discharge letter.
- **Fix:** Sliders start unset ("—"), are saved only once touched, and untouched ones are left out of the note, PDF and AI prompt.

**C4. No password change, reset or two-step recovery.**
- **Location:** Sign-in; Settings › Account. *(code: no such routes in `server/src/main.rs`)*
- **Problem:** A forgotten password or a lost phone locks a person out for good. If it is the owner, the fix is editing the database by hand.
- **Fix:** Change password (old + new) for everyone. Owner can issue a one-time reset code for a staff member and reset their two-step. Give the owner printed recovery codes at setup. Log all of it.

**C5. Clinic details cannot be saved, so documents lack them.**
- **Location:** Settings › Clínica. *(code: `clinic` table only has a name, set once at setup)*
- **Problem:** NIF, address, ERS number and logo fields accept typing and keep nothing. Discharge letters, consent PDFs and reimbursement packs for insurers and ADSE carry only the clinic name, which cannot be changed either.
- **Fix:** Add the columns and `GET/PUT /clinic`, wire the form with a Save button, print the details in every PDF header.

**C6. Settings controls that pretend to work.**
- **Location:** Settings › Segurança, Portal do utente, Métodos de pagamento, Faturação, Agenda (overlap, waitlist, session lengths).
- **Problem:** The two-step switch can be turned "off" (the server still requires it). "Lock after inactivity" offers 30 and 60 minutes and changes nothing. "Charge monthly plans automatically" is on by default for a feature that doesn't exist. Invoicing says the current method is "Portal das Finanças (trabalhador independente)", the opposite of your 5 Nov decision. Nothing persists past leaving the page.
- **Fix:** Rule: a control is either wired or absent. Show fixed policies as read-only text ("Two-step: always on"). Replace unbuilt sections with one "Em breve" row each.

### Major

**M1. Settings shows the wrong person.** The profile card is chosen by role from three hardcoded names, so any therapist sees "Ana Rocha, ana@clinica.pt". Use `me` from context. *(code, and reproduced)*

**M2. Team shows sample data.** Hours are looked up in `src/data/mock.ts` by name; real staff get "—". The pay switch toasts "Available in phase 3" although pay is set in Finance › Salários. The server supports changing a role; the UI doesn't offer it. Invites can't be listed or revoked.

**M3. Dead ends for non-owners.** Finance stays in the rail for therapists and reception and opens a "only the owner sees this" page. "Password and security" is a stub for them. Hide what a role can't use.

**M4. Day view hides status on normal sessions.** Type and status lines only render on cards taller than 80 px; a 60-minute card is 66 px. So "Por fechar / A decorrer" never appears for 60-minute sessions, and 45- and 60-minute cards use two different layouts side by side. Lower the threshold and use one layout.

**M5. Week view drops Sunday and misplaces early sessions.** `days7.slice(0, 6)` hides Sunday entirely; anything before 08:00 is pinned to the top and anything past 21:00 is cut, while the time picker allows 07:00–22:00. Derive the range from opening hours and the week's appointments, as day view already does.

**M6. Scheduling is slower than every competitor.** No click on an empty slot, no drag to move or resize, one mixed column instead of one per therapist. Add click-to-book first (prefills date, time, therapist); it removes three pickers from the most frequent action in the app.

**M7. Patient pickers won't scale.** New Appointment and Record Payment use a plain dropdown of all patients, and the list route returns at most 500 in name order. Past 500 patients, people late in the alphabet can't be booked from the dropdown and don't appear in the list. Replace with a search field backed by `?q=`, and page the list.

**M8. Modals aren't modal for the keyboard.** Tab walks out of an open sheet into the page behind (reproduced); the background isn't `inert`. Trap focus and restore it to the opener on close.

**M9. Row actions are invisible.** The ⋯ button on payment, expense and document rows has opacity 0 until hover. It can't be discovered on touch or by looking. Show it at rest in a quieter tone.

**M10. Sign-in screen sells features that don't exist.** Apple, Google and passkey circles sit under the main button and only toast "later". Remove them (also: an Apple logo on a non-working button is against Apple's own rules).

**M11. Forms validate by disabling the button and saying nothing.** Amount accepts "abc" and "-5" with no message; NIF has no check-digit test; phone and email are free text; no duplicate-patient warning. DESIGN.md already asks for "inline errors that say how to fix it".

**M12. Windows menus are full of stubs.** Help, Send Feedback, Redo, Minimize, Zoom, Full Screen and Bring All to Front all show a "Preview" toast in the real app. Wire the window commands to Tauri, remove the rest.

**M13. Server messages are English inside a Portuguese app.** Known and listed in STATUS; validation errors still arrive untranslated. Send the language in a header.

### Minor

- **Month names:** "Setembro De 2026" in closed months (capital "De") next to "outubro de 2026".
- **Money format:** "472 €", "936,40 €" and "472,00 €" on the same screens; pick one rule per table so columns align.
- **Now-line** draws through the card title like a strike-through; put it under the cards or stop it at the hour column.
- **First hour label** (8:00) is missing in day and week views.
- **Rail tooltip** stays up after a click and covers the first sections-column item.
- **"Sessões hoje 7"** includes the group class that is also counted in "Aulas de grupo 1".
- **Overview** shows "-98% da receita" for a loss; hide the ratio when the result is negative.
- **Stat cards** in Month Close contradict the "plain figures, no stat cards" rule used everywhere else.
- **"Registar…" invoice badge** is a 20 px-high badge acting as a button; invoice links are 18 px. Make them real small buttons (24 px minimum).
- **Sidebar label** "Exportar para contabili…" is cut at 220 px; shorten to "Exportar".
- **Search** opens Today when you pick a session instead of opening that appointment; the debounce doesn't work because `SearchResults` is defined inside `App` and remounts on every keystroke.
- **Minor check** uses year subtraction, so 18-year-olds get guardian fields.
- **"Bem-vindo de volta"** greets someone signing in for the first time; and it is masculine only.
- **Settings overview** values are literals ("Email, SMS", "Seg–Sáb", "6", "Ollama", "Ligado") and "Não construído" is developer language; use "Em breve".
- **Access log** shows 200 rows with no date filter, search or export; its description omits that it holds patient-file views.
- **Two-step code** doesn't submit on the sixth digit.
- **Date field** inside `DateInput` has no accessible label of its own in one form.
- **Salaries** are gross only; the monthly result ignores employer social security, so profit is overstated.

## 4. Incomplete and hidden nooks

- `src/data/mock.ts` is still imported by `Team.tsx`; sample staff names leak into the real app through it and through `Settings.tsx`.
- The default `toast()` text "Pré-visualização: esta ação ainda não está ligada" is reachable in production from about ten places (six menu commands, four Settings rows and Edit Profile).
- `teste-fatura.pdf` is still in the project root (flagged in STATUS on 9 Nov).
- About text and the three version numbers (app 0.2.0, About "0.4", server 0.11.0) disagree.
- Hash navigation (`#finance`) bypasses the Back/Forward history.
- The ≤760 px drawer layout exists but the window minimum is 1024 px, so it is dead code on desktop; at 700 px in the preview one alert row clips.
- Overlap layout divides width by "direct clashes + 1", so three sessions that overlap in a chain can sit on top of each other.
- No auto-update and no signed builds: every fix means reinstalling by hand on each computer.
- Session ends when the server is unreachable at launch: the sign-in screen shows an error with no Retry and no way back to "Connect".
- `OPEN_QUESTIONS.md` still lists unapproved consent texts; the dry-needling consent can't be signed until approved, and the patient tab says so correctly.
